# HTTPS 보안 자물쇠 및 인증서 가이드

모바일 브라우저로 EQT QR 코드를 스캔하면 주소창에 신뢰할 수 있는 공식 녹색 자물쇠(🔒)가 표시됩니다. 본 문서는 EQT LAN-TLS 시스템의 암호학적 원리와 문제 진단법을 설명합니다.

---

## 로컬 네트워크 전송에 HTTPS가 필수적인 이유

기존의 로컬 네트워크 전송 도구들은 암호화되지 않은 `http://`로 파일을 제공했습니다. 그러나 최신 운영체제와 모바일 브라우저는 일반 HTTP에 대해 매우 엄격한 보안 제한을 적용합니다.

### 1. iOS Safari의 1.5GB 메모리 한계 (OOM 비정상 종료)
암호화되지 않은 일반 `http://` 환경에서 Apple iOS WebKit 샌드박스는 파일의 저장소 직접 쓰기 스트림을 차단하고 수신되는 모든 데이터 조각을 브라우저 힙 메모리에 강제로 누적시킵니다. 그 결과, 일반 HTTP로 1.5GB~2GB 이상의 대용량 파일을 전송받으려 하면 Safari 탭이 메모리 부족(Out-Of-Memory)으로 즉시 강제 종료됩니다. **오직 신뢰할 수 있는 HTTPS 환경에서만 WebKit은 디스크로의 온전한 직접 스트리밍 쓰기 권한을 부여합니다.**

### 2. 최신 웹 플랫폼 API 제한
W3C 표준 사양에 따라 클립보드 자동 동기화, 시스템 네이티브 공유 시트(Web Share API), 하드웨어 가속 Web Crypto API 등은 **보안 컨텍스트(HTTPS)**에서만 실행이 허용되며, 일반 HTTP에서는 브라우저에 의해 강제로 비활성화됩니다.

### 3. 공용 Wi-Fi 환경의 패킷 도청 방지
카페, 호텔, 공유 오피스 등 개방된 Wi-Fi 환경에서는 평문 HTTP 전송 시 간단한 패킷 캡처 도구만으로도 개인 사진이나 업무용 문서를 손쉽게 도청당할 수 있습니다.

## EQT가 로컬 네트워크에서 공적 WebPKI 녹색 자물쇠를 구현하는 원리

1. **Let's Encrypt 전용 와일드카드 인증서**:
   데스크톱 클라이언트는 최초 실행 시 로컬에서 고유한 ECDSA P-256 개인키를 생성합니다. Cloudflare 서버리스 오케스트레이션을 통해 **Let's Encrypt**와 ACME DNS-01 챌린지를 완료하고 해당 기기 전용 와일드카드 인증서(`*.<NodeID>.direct.eqt.net.im`)를 발급받습니다.
2. **무상태 수학적 루프백 DNS (`eqt-dns`)**:
   스마트폰이 `https://192-168-1-50.<NodeID>.direct.eqt.net.im:8080/`와 같은 주소를 조회하면, 권위 DNS는 데이터베이스 조회 없이 순수 메모리 연산으로 접두사를 로컬 IP `192.168.1.50`으로 즉각 변환하여 반환합니다.
3. **공적 루트 CA 신뢰 + 로컬 Wi-Fi 직접 스위칭**:
   모바일 브라우저는 내장된 Let's Encrypt 루트 인증서를 통해 검증을 통과하여 녹색 자물쇠를 표시합니다. 이때 **100%의 TCP 데이터 패킷은 외부 인터넷을 전혀 거치지 않고 오직 로컬 공유기나 스위치를 통해 물리적으로 직접 전송됩니다.**
