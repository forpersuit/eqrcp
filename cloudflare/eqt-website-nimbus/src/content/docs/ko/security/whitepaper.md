# 보안 및 프라이버시 백서

중앙 집중식 클라우드 스토리지와 메신저 플랫폼이 데이터 교환을 독점하는 오늘날, 개인 사진의 클라우드 자동 검열, 인공지능 모델 학습용 데이터 무단 수집, 암호화되지 않은 Wi-Fi 상에서의 패킷 도청 등 심각한 프라이버시 침해가 빈번히 발생하고 있습니다.

EQT는 개발 초기부터 **"제1원리에 기반한 프라이버시 보호, 물리적 현실 최우선 (Privacy by First Principles & Physical Reality First)"**이라는 엔지니어링 철학을 고수해 왔습니다. 본 백서는 EQT의 보안 아키텍처와 암호화 설계를 공개합니다.

---

## 3대 핵심 보안 불변성 (Invariants)

1. **엄격한 제로 클라우드 스토리지 (Zero Cloud Relay)**:
   1MB의 코드 조각이든 100GB의 원본 영상 압축 파일이든, 데이터 페이로드는 송신자와 수신자 사이에 직접 연결된 물리적 네트워크 소켓을 통해서만 흐릅니다. EQT는 파일 저장 서버, 외부 릴레이, 클라우드 캐시를 일절 운영하지 않습니다.
2. **외부 유출 제로 디바이스 개인키**:
   로컬 TLS 암호화에 필요한 ECDSA P-256 개인키는 컴퓨터 내부의 고엔트로피 시스템 난수를 통해 물리적으로 생성되며 POSIX `0600` 원자적 파일 권한으로 보호됩니다. **개인키는 네트워크를 통해 외부로 전송되지 않습니다.**
3. **완전 휘발성 모바일 샌드박스 격리**:
   모바일 기기는 표준 모바일 브라우저(iOS Safari, Android Chrome)의 격리된 샌드박스 내에서만 통신합니다. 브라우저 탭을 닫는 즉시 실행 컨텍스트가 파기되며 모바일 기기에 어떠한 백그라운드 프로세스도 상주하지 않습니다.

## LAN-TLS 프로토콜 아키텍처

### 1. 기존 업계 방식의 기술적 결함
로컬 네트워크 직접 전송에서 "모바일 편의성"과 "엄격한 암호학적 보안"은 오랫동안 양립하기 어려웠습니다:

| 방식 | 작동 메커니즘 | 취약점 및 보안성 평가 |
| :--- | :--- | :--- |
| **평문 HTTP** | `http://192.168.x.x` 직접 통신 | ❌ **공용 Wi-Fi에서 도청 가능**; iOS Safari 대용량 파일 (>1.5GB) 다운로드 시 메모리 크래시 발생. |
| **자체 서명 인증서** | 로컬 자체 CA 임시 인증서 | ❌ **브라우저의 위험 경고창 강제 유발**, 사용자에게 보안 경고를 무시하는 위험한 보안 습관을 학습시킴. |
| **클라우드 중계** | 외부 프록시 서버로 파일 업로드 | ❌ **프라이버시의 완전한 상실**; 외부 인터넷 업로드 속도 및 클라우드 대역폭 제한에 종속됨. |
| **공유 개인키 내장** | 정적 와일드카드 인증서 및 개인키 번들 | ❌ **치명적인 유사 보안**. 개인키가 공개된 대칭키가 되어 동일 LAN 내에서 중간자 공격(MITM)에 무방비 노출. |
| **EQT LAN-TLS (본 시스템)** | **Let's Encrypt 기기 전용 인증서 + 무상태 DNS** | ✅ **개인키 유출 제로 + 공적 WebPKI 녹색 자물쇠 🔒 + 순수 로컬 물리 회선 한계 속도**. |

### 2. EQT LAN-TLS 시퀀스 아키텍처

EQT는 **로컬 ECDSA 키 쌍 생성**, **Cloudflare Workers 기반의 서버리스 ACME DNS-01 챌린지 조율**, 그리고 **무상태 수학적 권위 루프백 DNS (`eqt-dns`)**를 완벽하게 통합합니다:

```
+---------------------------------------------------------------------------------------------------+
| 1. 클라이언트 로컬 키 생성 (컴퓨터)                                                                |
|    - 컴퓨터에서 전용 ECDSA P-256 개인키를 생성하고 POSIX 0600 권한으로 보관.                        |
|    - 개인키는 머신을 떠나지 않으며 오직 CSR (*.<NodeID>.direct.eqt.net.im)만 추출.                 |
+--------------------------------------------------+------------------------------------------------+
                                                   |
                                                   | (1) 재전송 방지 타임스탬프가 포함된 CSR 전송
                                                   v
+---------------------------------------------------------------------------------------------------+
| 2. Cloudflare ACME 게이트웨이 조율 (Serverless)                                                   |
|    - Worker가 CSR 서명과 요청 속도를 검증하고 CA(Let's Encrypt)에 인증서 주문을 제출.             |
|    - DNS-01 TXT 챌린지 토큰을 받아 eqt-dns에 임시 _acme-challenge 레코드를 등록.                  |
|    - Let's Encrypt가 TXT 레코드를 검증하고 X.509 인증서를 발급. Worker는 즉시 TXT 레코드를 삭제.   |
+--------------------------------------------------+------------------------------------------------+
                                                   |
                                                   | (2) 공개 인증서 체인(fullchain.pem) 반환
                                                   v
+---------------------------------------------------------------------------------------------------+
| 3. 로컬 서비스 초기화 및 모바일 기기 접속                                                         |
|    - 컴퓨터가 privkey.pem과 cert.pem을 로드하고 TLS 1.3 소켓을 바인딩.                            |
|    - 스마트폰이 https://192-168-1-50.<NodeID>.direct.eqt.net.im:8080/ 주소의 QR 코드를 스캔.     |
+--------------------------------------------------+------------------------------------------------+
                                                   |
                                                   | (3) 모바일 기기가 DNS 질의 시작
                                                   v
+---------------------------------------------------------------------------------------------------+
| 4. 무상태 수학적 루프백 DNS (eqt-dns)                                                             |
|    - 권위 DNS가 쿼리를 수신하고 메모리에서 `192-168-1-50` 접두사를 수학적으로 로컬 IP로 즉각 분해. |
|    - 1ms 미만의 시간에 A 레코드 192.168.1.50(TTL=300s)을 응답. 데이터베이스 조회 없음, 로그 없음.  |
+--------------------------------------------------+------------------------------------------------+
                                                   |
                                                   | (4) LAN 내부 직접 소켓 핸드셰이크
                                                   v
+---------------------------------------------------------------------------------------------------+
| 5. 종단간 TLS 1.3 LAN 물리 회선 속도 전송                                                         |
|    - 모바일 브라우저가 Let's Encrypt 신뢰 체인을 검증하여 경고창 없이 녹색 자물쇠 🔒를 표시.     |
|    - 고처리량 AEAD 암호화(AES-GCM / ChaCha20-Poly1305); 모든 데이터가 100% 로컬 네트워크로만 흐름.|
+---------------------------------------------------------------------------------------------------+
```

### 3. 주요 기술적 강점

#### ① 암호학적 개인키 누출 제로 (중간자 공격 완전 차단)
각 EQT 컴퓨터는 고유한 Node ID를 가지며 로컬에서 자체 암호화 키를 생성합니다. 인증서는 오직 `*.<NodeID>.direct.eqt.net.im`에 대해서만 발급됩니다. **네트워크 전체에 공유되거나 공용으로 쓰이는 개인키는 존재하지 않습니다.**

#### ② 순수 수학적 무상태 루프백 DNS
권위 해석 클러스터(`eqt-dns`)는 사용자 IP 데이터베이스를 저장하지 않습니다. 메모리 상에서 알고리즘을 통해 `192-168-1-50`을 실제 내부 사설 IP인 `192.168.1.50`으로 즉각 분해하여 응답하므로 무한한 수평 확장이 가능합니다.

#### ③ 공식 대용량 쿼터 및 Multi-CA 탄력성
일반적인 공적 CA의 엄격한 발급 제한과 달리, EQT는 Let's Encrypt의 공식 고용량 쿼터(주당 20,000건 이상)를 부여받아 운영되고 있으며 지능형 Multi-CA 백업 레이어를 내장하여 무중단 글로벌 가용성을 보장합니다.

#### ④ 오프라인 폐쇄망 자동 대체 (Air-Gap)
인터넷이 연결되지 않은 완전히 고립된 망에서 처음 실행되더라도, EQT는 임시 대체 인증서를 즉시 초기화하여 로컬 전송이 중단 없이 작동하도록 보장하며, 이후 인터넷이 연결되면 백그라운드에서 신뢰할 수 있는 공적 인증서로 자동 업그레이드됩니다.
