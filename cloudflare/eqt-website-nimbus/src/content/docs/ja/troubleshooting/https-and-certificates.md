# HTTPS 緑の南京錠と証明書ガイド

モバイルブラウザで EQT の QR コードをスキャンすると、URL バーに信頼された「緑の南京錠（🔒）」アイコンが表示されます。このガイドでは、EQT の LAN-TLS システムの暗号化原則と運用診断について説明します。

---

## なぜローカルネットワーク転送に HTTPS が必要なのか

従来の LAN 転送ツールは、平文の `http://` でデータを配信していました。しかし、最新のオペレーティングシステムやブラウザでは、プレーン HTTP に対して極めて厳しい技術的制約が課されています。

### 1. iOS Safari の 1.5GB メモリトラップ (OOM クラッシュ)
平文の `http://` 環境下では、Apple iOS WebKit のサンドボックス制限により、ストレージへの直接ストリーミング書き込みがブロックされ、受信データチャンクがブラウザのヒープメモリに強制的に蓄積されます。その結果、1.5GB〜2GB を超える大容量ファイルを平文 HTTP でダウンロードしようとすると、Safari のタブがメモリ不足（Out-Of-Memory）でクラッシュします。**正規の HTTPS コンテキストでのみ、WebKit はディスクへの無制限ストリーミング直接書き込みを許可します。**

### 2. 最新 Web プラットフォーム API の制限
W3C 仕様により、クリップボードの読み書き、モバイルの共有シート（Web Share API）、ハードウェア暗号化 API などは、**安全なコンテキスト（HTTPS）**でのみ実行が許可されています。平文 HTTP ではこれらの機能が無効化されます。

### 3. 公共 Wi-Fi における盗聴防止
カフェ、ホテル、コワーキングスペースなどの共有 Wi-Fi では、平文 HTTP 通信は簡単にパケットキャプチャによって盗聴され、写真や仕事の書類が漏洩する危険があります。

## EQT がローカルネットワークで公的 WebPKI の緑の南京錠を実現する仕組み

1. **Let's Encrypt 専用ワイルドカード証明書**：
   PC での初回起動時、クライアントはローカルで ECDSA P-256 秘密鍵を生成します。Cloudflare Workers を介した自動オーケストレーションにより、**Let's Encrypt** と ACME DNS-01 チャレンジを完了し、その端末専用のワイルドカード証明書（`*.<NodeID>.direct.eqt.net.im`）を取得します。
2. **ステートレス数学ループバック DNS (`eqt-dns`)**：
   スマートフォンが `https://192-168-1-50.<NodeID>.direct.eqt.net.im:8080/` をスキャンすると、権威 DNS はメモリ上でプレフィックスを内部 IP `192.168.1.50` に瞬時に変換して返します。
3. **公的ルート CA の信頼 + ダイレクト Wi-Fi スイッチング**：
   スマホのブラウザは組み込みの Let's Encrypt ルート証明書で安全性を検証し、緑の南京錠を表示します。その間、**100% の TCP データパケットはローカルルーター経由でのみ直接送受信され、外部サーバーを経由しません**。
