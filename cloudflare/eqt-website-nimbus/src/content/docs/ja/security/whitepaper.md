# セキュリティ＆プライバシー白書

集中型クラウドストレージやメッセージングアプリがデータ交換の主流となった現代において、個人の写真のスキャン、AI モデルへの無断学習データ取り込み、暗号化されていない Wi-Fi 上での盗聴など、プライバシーを巡る構造的な問題が深刻化しています。

EQT は開発当初より、**「第一原理によるプライバシー保護、物理的現実を最優先（Privacy by First Principles & Physical Reality First）」**という設計哲学を貫いています。本文書では、EQT のセキュリティ構造と暗号設計を公開します。

---

## 3 つの核心的セキュリティ不変項

1. **厳格なゼロクラウドストレージ（Zero Cloud Relay）**：
   1MB のコード断片であれ 100GB の 4K 映像であれ、すべてのデータストリームは送信元と受信先の間に確立された直接の物理ネットワークソケットのみを経由します。EQT はファイル保存サーバー、外部リレー、クラウドキャッシュを一切持ちません。
2. **外部漏洩ゼロのデバイス秘密鍵**：
   ローカル TLS 暗号化に必要な ECDSA P-256 秘密鍵は、PC の高エントロピー乱数から端末内部で物理的に生成され、POSIX `0600` の厳格なファイル権限で保存されます。**秘密鍵がネットワーク経由で送信されることは絶対にありません。**
3. **完全揮発性メモリ動作とエフェメラルセッション**：
   モバイルデバイスは標準ブラウザのサンドボックス内でのみ動作します。タブを閉じた瞬間に実行コンテキストが破棄され、モバイル端末にバックグラウンドプロセスや追跡データは一切残りません。

## LAN-TLS プロトコルアーキテクチャ

### 1. 従来手法の技術的欠陥
ローカル直接転送において、「モバイル端末の手軽さ」と「厳格な暗号学的セキュリティ」は従来対立してきました：

| 手法 | 動作メカニズム | 脆弱性とセキュリティ評価 |
| :--- | :--- | :--- |
| **平文 HTTP** | `http://192.168.x.x` による直接通信 | ❌ **公共 Wi-Fi で盗聴可能**。iOS Safari で大容量ファイル (>1.5GB) 転送時にメモリクラッシュが発生。 |
| **自己署名証明書** | 一時的なローカル CA 証明書 | ❌ **ブラウザの危険な警告画面**を強制し、ユーザーにセキュリティ警告を無視する危険な習慣を植え付ける。 |
| **クラウド中継** | リレーサーバーへのファイルアップロード | ❌ **プライバシーの完全な喪失**。上り回線速度やクラウドの帯域制限を受ける。 |
| **共通秘密鍵の同梱** | 静的ワイルドカード証明書と秘密鍵の内蔵 | ❌ **壊滅的な疑似セキュリティ**。秘密鍵が事実上の共通鍵となり、同一 LAN 内での中間者攻撃 (MITM) が可能。 |
| **EQT LAN-TLS (本システム)** | **Let's Encrypt 端末専用証明書 + ステートレス DNS** | ✅ **秘密鍵の漏洩ゼロ + 公的 WebPKI 緑の南京錠 🔒 + 物理回線の限界速度**。 |

### 2. EQT LAN-TLS シーケンス設計

EQT は、**ローカル ECDSA 鍵生成**、**Cloudflare Workers によるサーバーレス ACME DNS-01 オーケストレーション**、および**ステートレス数学的権威ループバック DNS (`eqt-dns`)** を融合しています：

```
+---------------------------------------------------------------------------------------------------+
| 1. クライアントでのローカル鍵生成 (PC)                                                              |
|    - 端末内で専用の ECDSA P-256 秘密鍵を生成、POSIX 0600 権限で保存。                               |
|    - 秘密鍵は端末外に出ず、CSR (*.<NodeID>.direct.eqt.net.im) のみを出力。                          |
+--------------------------------------------------+------------------------------------------------+
                                                   |
                                                   | (1) 再送防止タイムスタンプ付き CSR 送信
                                                   v
+---------------------------------------------------------------------------------------------------+
| 2. Cloudflare ACME ゲートウェイ (Serverless)                                                      |
|    - Worker が CSR 署名とレートリミットを検証し、Let's Encrypt に注文を発行。                      |
|    - DNS-01 TXT チャレンジを取得し、eqt-dns に一時的な _acme-challenge を動的登録。                |
|    - Let's Encrypt が TXT レコードを検証して X.509 証明書を発行。Worker は即座に TXT を削除。     |
+--------------------------------------------------+------------------------------------------------+
                                                   |
                                                   | (2) 公開証明書チェーン (fullchain.pem) を返却
                                                   v
+---------------------------------------------------------------------------------------------------+
| 3. ローカルサービス初期化とモバイル接続                                                           |
|    - PC が秘密鍵と証明書を読み込み、TLS 1.3 ソケットをバインド。                                  |
|    - スマホが https://192-168-1-50.<NodeID>.direct.eqt.net.im:8080/ をスキャン。                  |
+--------------------------------------------------+------------------------------------------------+
                                                   |
                                                   | (3) スマホが DNS 問い合わせを実行
                                                   v
+---------------------------------------------------------------------------------------------------+
| 4. ステートレス数学ループバック DNS (eqt-dns)                                                     |
|    - 権威 DNS が受信し、メモリ上でプレフィックス `192-168-1-50` をアルゴリズム変換。               |
|    - <1ms で A レコード 192.168.1.50 (TTL=300s) を応答。データベース参照なし、ログ記録なし。     |
+--------------------------------------------------+------------------------------------------------+
                                                   |
                                                   | (4) LAN 内でのダイレクトソケットハンドシェイク
                                                   v
+---------------------------------------------------------------------------------------------------+
| 5. エンドツーエンド TLS 1.3 LAN 物理回線速度転送                                                  |
|    - モバイルブラウザが Let's Encrypt ルート信頼を検証し、警告なしで緑の南京錠 🔒 を表示。        |
|    - 高スループット AEAD 暗号化 (AES-GCM / ChaCha20-Poly1305)。データは 100% ローカル内のみ流通。  |
+---------------------------------------------------------------------------------------------------+
```

### 3. 主な技術的優位性

#### ① 暗号学的な秘密鍵漏洩ゼロ（中間者攻撃の完全排除）
各 EQT 端末は固有の Node ID を持ち、端末内部で鍵ペアを生成します。証明書は `*.<NodeID>.direct.eqt.net.im` に限定して発行されます。**共有秘密鍵はネットワーク上に一切存在しません。**

#### ② 純粋な数学的ステートレス DNS ループバック
権威 DNS クラスタ（`eqt-dns`）は、ユーザーの IP アドレスを保存しません。メモリ上でプレフィックスを内部 IP に分解して応答するため、超高速レスポンスと無限の水平スケーラビリティを備えています。

#### ③ 公式ハイキャパシティ枠と Multi-CA レジリエンス
通常の ACME 認証には厳しい週次発行制限がありますが、EQT は Let's Encrypt の公式高クォータ枠（週 20,000 件以上）を取得しており、グローバルな安定性を確保しています。

#### ④ オフライン環境でのシームレスなフォールバック
完全なオフライン環境で初回起動した場合でも、一時的な自己署名証明書で即座にローカル通信を維持し、ネット接続時にシームレスに公的証明書へ昇格します。
