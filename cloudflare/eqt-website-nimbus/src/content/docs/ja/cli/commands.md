# CLI コマンドリファレンス

EQT のコアエンジンは Go 言語で記述されており、軽量かつ高スループットなコマンドラインインターフェース（CLI）を提供します。GUI のないヘッドレスサーバー、ローカル開発環境のターミナル、自動化スクリプトでシームレスに動作します。

---

## 主要なサブコマンド

### 1. ファイルまたはディレクトリの送信 (Send)
サブコマンドを省略してパスを指定した場合、EQT はデフォルトで送信モードとして動作します：
```bash
# 単一ファイルを送信
eqt Document.pdf

# 複数ファイルを指定し、ポートを指定して送信
eqt --port 8080 Video.mp4 Presentation.pptx

# フォルダ全体を送信 (メモリ上で即時ストリーミング ZIP 圧縮)
eqt /home/user/Projects/
```

### 2. ファイルの受信 (Receive)
```bash
# 受信モードを起動してスマホからのアップロードを待機
eqt receive

# 保存先ディレクトリを指定 (短縮フラグ -o)
eqt receive -o ~/Downloads
```

### 3. LAN コラボレーション (Chat)
```bash
# ヘッドレスで LAN コラボレーションサービスを起動
eqt chat

# 起動と同時にデフォルトブラウザで Web コンソールを開く
eqt chat --browser
```

### 4. インタラクティブ設定ウィザード (Config)
```bash
# ターミナル上でネットワークインターフェースやポートを設定
eqt config
```

### 5. シェル自動補完スクリプトの生成 (Completion)
```bash
eqt completion bash > /etc/bash_completion.d/eqt
eqt completion zsh > "${fpath[1]}/_eqt"
```

## グローバルオプション一覧

| オプション | 短縮 | デフォルト値 | 説明 |
| :--- | :---: | :---: | :--- |
| `--interface` | `-i` | 自動検出 | バインドするネットワークインターフェースを強制指定 (例: `eth0`, `wlan0`, `Wi-Fi`) |
| `--port` | `-p` | `0` (ランダム) | リッスンポート番号 (`0` で空きポートを自動選択) |
| `--bind` | | `0.0.0.0` | リッスン IP アドレス (短縮フラグなし) |
| `--browser` | `-b` | `false` | 起動時にデフォルトブラウザで自動的に開く |
| `--secure` | `-s` | `true` | Let's Encrypt による WebPKI HTTPS 暗号化を有効化 |
| `--output` | `-o` | ダウンロードフォルダ | 受信したファイルの保存先ディレクトリ (受信モード専用) |
| `--keep-alive` | `-k` | `false` | 転送完了後もサーバープロセスを終了せずに維持する |
| `--quiet` | `-q` | `false` | プログレスバーを非表示にし、エラーログのみを出力 |
| `--zip` | `-z` | `false` | 複数ファイルを強制的に 1 つの ZIP にまとめて送信 |
| `--fqdn` | `-d` | 自動 | 生成される QR コードのホスト名 / ドメイン名を上書き |
| `--path` | | ランダム文字列 | HTTP ルートの URL パスプレフィックスを指定 (例: `/share`) |
| `--config` | `-c` | デフォルトパス | 外部 YAML 設定ファイルのパスを指定 |
| `--list-all-interfaces` | `-l` | `false` | 仮想アダプタを含むすべてのネットワークインターフェースを一覧表示 |
| `--reversed` | `-r` | `false` | ターミナルの QR コードの明暗コントラストを反転 |
| `--tls-cert` | | 空 | カスタム TLS 証明書のパス (完全オフライン環境用) |
| `--tls-key` | | 空 | カスタム TLS 秘密鍵のパス (完全オフライン環境用) |
