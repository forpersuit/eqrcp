# 安全与隐私白皮书

在各类云盘、社交通讯软件充斥日常生活的当下，用户的数据隐私正遭受前所未有的严峻挑战：商业公司通过云端扫描用户私密相册、未经授权使用用户文件训练大模型、明文通信在公共 Wi-Fi 下遭遇同网嗅探与中间人攻击。

EQT 从立项第一天起就遵循**“物理真实性优先与零信任隐私”（Privacy by First Principles）**哲学。本文公开披露 EQT 的安全架构与密码学实现。

---

## 核心安全不变量 (Core Security Invariants)

1. **绝对零数据上云 (Zero Cloud Storage)**：
   无论传输 1MB 的代码片段还是 100GB 的 4K 蓝光影视文件，数据载荷（payload）仅在发送端与接收端两台设备间直接建立的物理套接字（Socket）中流转。EQT 没有任何文件转存、中继或云端缓存服务器。
2. **设备私钥终身永不出机 (Zero-Leak Device Private Key)**：
   局域网 TLS 加密所需的 ECDSA P-256 私钥由您的电脑本地高强度随机源物理生成，安全持久化于本地受保护目录（POSIX `0600` 权限），**绝不通过网络上传至云端**。
3. **免装移动 App 且绝不留存后台驻留**：
   移动端依托原生移动浏览器（iOS Safari、Android Chrome 等）的受限安全沙箱运行，传输结束关闭标签页即物理释放运行上下文，不在移动设备上安装任何常驻保活进程。

## LAN-TLS 安全协议运作原理解析

### 1. 行业传统方案的技术死穴
在跨平台局域网直传中，“零门槛”与“高安全”长期存在尖锐的技术矛盾：

| 方案分类 | 运作机制 | 致命缺陷与安全性评估 |
| :--- | :--- | :--- |
| **纯明文传输 (HTTP)** | 直接通过 `http://192.168.x.x` 传输 | ❌ **公共 Wi-Fi 极易被嗅探**；且 iOS WebKit 会触发大文件（>1.5GB）内存溢出崩溃。 |
| **自签名证书 (Self-Signed)** | 本地生成临时自签 CA 证书 | ❌ **浏览器弹出刺眼红色安全警告**，迫使用户养成忽略安全警告的危险习惯。 |
| **云端中继 (Cloud Relay)** | 文件上传至公网服务器中转 | ❌ **彻底丧失数据隐私**；受限于公网宽带上行与云端中转限速，无法发挥本地局域网的高速硬件直连优势。 |
| **共享通配符私钥分发** | 官方申请通配符证书并将私钥打包进客户端 | ❌ **灾难性假安全**。私钥退化为公开对称秘密，任何恶意用户均可发动局域网主动中间人拦截（Active MITM）。 |
| **EQT LAN-TLS (本项目)** | **Let's Encrypt 专属设备通配符 + 数学无状态回环 DNS** | ✅ **零私钥泄漏 + 权威机构 WebPKI 绿锁 🔒 + 纯局域网物理线速传输**。 |

### 3. 四大核心设计优势

#### ① 密码学级别的私钥零泄漏（防中间人攻击）
每个 EQT 客户端拥有唯一的设备 Node ID，并在本地生成专属私钥，申请的证书仅对该设备的 `*.<NodeID>.direct.eqt.net.im` 生效。**网络上不存在任何公用的通用私钥**，哪怕同局域网内有其他 EQT 用户，也绝对无法解密或伪造您的通信会话。

#### ② 纯数学计算的无状态回环 DNS（极速与抗并发）
自建权威解析集群（`eqt-dns`）无需建立任何 IP 映射数据库。通过算法将形如 `192-168-1-50` 的域名前缀实时还原为物理内网 IP `192.168.1.50`，响应时间低于 1 毫秒，天然具备无限水平扩容能力。

#### ③ 官方高配额通道与 Multi-CA 弹性容灾
传统 ACME 方案常受限于公共 CA 单主域每周 50 张的速率壁垒。EQT 已获 Let's Encrypt 官方专用高配额通道保障（单周支持 20,000+ 张证书签发）；同时云端编排层内建 Multi-CA 智能熔断与双轨容灾机制，确保全球海量设备在高并发置备时全天候稳定可用。

#### ④ 自动降级与离线容错保障
若用户在纯物理离线（无外网）机房或无公网连接的 Wi-Fi 下首次启动，系统会自动启动自适应降级机制，以本地临时证书保障局域网物理传输不断流。连入外网后即可自动静默完成公信证书的置备与无感升级。

## 内存安全与会话即毁

- **流式分块打包（Zero-Tempfile Streaming）**：发送整个文件夹时，文件流直接在内存网络套接字中完成流式 Zip 压缩并向外推送，不在磁盘创建任何易泄密的未擦除临时文件。
- **Chat 会话物理隔离**：即时消息与剪贴板数据仅驻留在操作系统的易失性内存（RAM）中。会话结束、窗口关闭或服务终止时，内存数据立即被系统释放，磁盘上绝不留存任何明文历史记录。
