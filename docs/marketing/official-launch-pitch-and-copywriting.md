## 1. 创作者初心与第一性产品概览

### 1.1 这是我的第一个正式数字产品
EQT 是我独立构思、打磨并正式推向市场的第一个数字产品。它的诞生源于长年累月在 Windows/Linux 电脑与手机（iOS/Android）之间传输文件、同步代码与剪贴板时的真实痛苦。

### 1.2 核心模式与交互抽象
打开 EQT 桌面端，核心分为 3 大模式，满足点对点传输的全场景：
1. **Share 模式（桌面端 ➔ 移动端）**：单文件、多文件或整个目录，桌面端一键生成专属二维码，移动端扫码直接高速下载（目录自动流式打包为 zip）。
2. **Receive 模式（移动端 ➔ 桌面端）**：桌面端开启接收节点，移动端扫码进入极简上传界面，拖拽或选取相册/文件直传电脑指定文件夹。
3. **Chat 模式（双向即时轻量交互）**：手机扫码进入点对点局域网加密房间，双向文字、长代码、API Token、图片即时互通，带有一键复制到剪贴板与用完即毁特性。

### 1.3 核心特色 (Core Highlights)
* **移动端彻底免装 App**：接收端与发送端无需在应用商店下载任何客户端，原生相机或主流浏览器扫码即用。
* **零云端、100% 局域网物理满速**：传输完全在本地 WiFi / 局域网内直连，突破外网带宽瓶颈，跑满 10MB/s ~ 100MB/s+ 物理网卡性能。
* **Zero-Config LAN-TLS 本地绿锁加密**：解决传统局域网 HTTP 下移动端浏览器禁止调用现代 Web API（剪贴板、Web Share 等）及安全警告的行业通病，实现原生信任的 HTTPS 加密。
* **极度轻量与多形态**：极客热爱的终端 CLI（ASCII 动态二维码）、常驻托盘的桌面 GUI、以及 Windows 右键菜单深度集成（`Share with eqt`）。
* **基础功能永久免费**：每日提供充足的免限制极速传输与日常 Chat 额度，无恶心广告，无后台流氓行为。

### 1.4 坦诚说明当前的物理局限
* **网络范围约束**：目前仍是一款纯局域网工具，要求电脑与移动设备处于同一个 WiFi 或局域网子网下（有联网能力时可激活安全证书，但传输本身不经过任何云端中继）。

### 正文完整稿

各位社区的朋友，大家好：

今天，非常开心、也有点忐忑地向大家正式介绍我独立打磨的第一个数字产品 —— **EQT (Easy QR Transfer)**。

#### 1. 起点：为什么在 2026 年，跨设备传东西依然这么别扭？

在日常的工作与生活流中，以下场景大家一定非常熟悉：
- 手机刚拍了段几百兆的 4K 视频想要发给 Windows 剪辑，发现苹果的 AirDrop 根本无法跨出生态；
- 电脑刚配置好一段测试用 API Token、密码或命令，想拷到手机上，只能打开微信“文件传输助手”或企业协作软件 —— 文本被存到了公网云端服务器不说，还经常被企业 IT 审计或格式折叠；
- 朋友、同事或客户就坐在你旁边，想互传一份设计稿或录音文件，市面上好用的工具却往往要求**对方手机也必须先去应用商店下载一个 50MB 的 App 并完成配对** —— 很多时候，等安装配对折腾完，沟通的耐心早已消磨殆尽；
- 至于云盘？先上传（忍受慢速）、手机再登录同一个账号、再下载，不仅浪费公共带宽，更让完全私密的数据在第三方云端走了一遭。

我不禁从第一性原理思考：**两个设备明明就在同一张办公桌上、连着同一个 WiFi，物理距离不过几十厘米，为什么数据非要绕地球半圈走云端？为什么非要强迫接收方安装一个可能一个月才打开一次的手机客户端？**

跨设备的数据流动，本该像呼吸一样自然。

#### 2. EQT 是什么？

EQT 是一款专注于**桌面端与移动端之间极速传输与即时轻量交互**的局域网工具。

它的底层逻辑极其纯粹：**电脑发起，手机扫码，即刻直连。**

打开软件，你会看到 3 个清晰的场景模式：
1. **Share 模式（电脑 ➔ 手机）**：选择单个文件、多张图片或一整个文件夹，电脑屏幕（或终端）即刻生成专属二维码。手机扫码直接以最高速度下载，多文件或目录会自动在内存中流式打包为 zip 压缩包，毫无额外等待。
2. **Receive 模式（手机 ➔ 电脑）**：电脑端开启接收监听，手机扫码打开极简 Web 页面，直接勾选相册或拖入大文件，直接写入电脑指定的本地目录。
3. **Chat 模式（跨端即时通讯与剪贴板同步）**：手机扫码进入专属的端到端加密局域网房间。两端可双向互发文本、代码、Token、截图与附件。支持移动端原生一键复制到剪贴板，用完随手关闭，会话即焚。

#### 3. 为什么选择 EQT？（核心产品特性）

* **📱 移动端彻底免装 App（Zero Mobile App）**  
  对接收端极致友好。只要手机有摄像头（原生相机扫码）或者任意现代浏览器，扫码即可使用，不需要让同事或朋友下载安装任何额外软件。
* **⚡ 跑满内网物理带宽（10MB/s ~ 100MB/s+）**  
  传输数据 100% 走本地物理局域网，不消耗公网流量，完全摆脱宽带上行与网盘限速瓶颈。几个 G 的大素材，内网瞬间传完。
* **🔒 业内首创的 Zero-Config LAN-TLS 本地安全绿锁**  
  以往在局域网 HTTP 下传输，手机浏览器经常弹窗警告“不安全”，且移动端系统直接禁止网页调用原生剪贴板和分享 API。EQT 在 v1.36 中实现了零配置局域网 TLS 证书环回，无需用户手动折腾根证书导入，扫码即拥有原生受信任的 HTTPS 绿锁。
* **🖥 随心所欲的使用形态**  
  - 极客喜爱的 **CLI 模式**：终端炫酷打印动态 ASCII 二维码，在无桌面环境的 Linux 服务器或 SSH 会话中堪称神兵利器；
  - 优雅轻量的 **桌面 GUI**：现代化窗口与系统托盘常驻，即开即用；
  - **Windows 深度集成**：选中文件右键“Share with eqt”，秒级完成分享。

#### 4. 坦诚说明：当前的局限与质朴的初心

作为我的第一个数字产品，我必须诚实地说明它现阶段的边界与我的初心：
- **同一 WiFi / 局域网限制**：EQT 当前是一款纯局域网软件，要求两台设备处于同一个 WiFi 或局域网子网下（在有公网能力时可一键激活安全证书，但即使不联网也完全支持内网互传，且传输本身绝不经过任何外部服务器中继）。
- **脚踏实地的目标**：我不打算在这里画宏大的技术饼。**先把局域网的效果做好，大家真正愿意用、觉得好用，就是我目前最大的目标。** 后续版本我们会根据大家的真实反馈，持续优化局域网体验并探索更多可能。

### 5.2 X (Twitter) 发推防降权规则
* **正文 100% 零外链**：Twitter 算法对推文正文包含的外部链接降权严重（曝光减少 50%~80%）。
* **First Reply 沉淀链接**：正文结尾只写“👇 体验地址与开源见评论区第 1 条”，在推文发出后的第一秒，自己回复第 1 条评论带上官网与 GitHub 链接。
* **配图与动图加持**：发推必须带一张**左边电脑终端二维码、右边手机原生扫码下载**的高清双拼图或录屏动图，视觉停留率（Dwell Time）直接决定算法推荐权重。

### 5.3 演示录屏动图 (GIF) 制作建议
* **长度**：控制在 8~12 秒之间，文件大小 <= 5MB。
* **分屏动效**：
  - 前 3 秒：电脑右键文件点击 `Share with eqt`，屏幕瞬间弹出清晰二维码；
  - 第 4~7 秒：镜头/分屏切至手机，原生相机对准屏幕一扫，弹窗轻点即打开网页；
  - 第 8~10 秒：手机网页进度条以几十兆每秒的速度飞速拉满，提示文件接收完成。
* **冲击力**：直观向所有潜在用户展示“原来跨设备传文件真的可以不用下 App、不用加好友、不用等上传”。
