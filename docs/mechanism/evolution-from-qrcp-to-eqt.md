# 从 qrcp 到 EQT：工程血统、演进历程与架构重塑对比

> **状态**：📘 工程演进与架构溯源（Architecture Evolution Reference）

> **适用版本**：v1.36.67+

## 核心结论概述

**合规与开源血统上**，EQT 保留了原项目 [`qrcp`](https://github.com/claudiodangelis/qrcp) 的发端与开源溯源，遵循 MIT License；  
**但在工程实质与架构体系上**，EQT 经历了一场彻底的**“特修斯之船（Ship of Theseus）”**式重塑：
- **原版代码目前在整个工程中仅占不到 3%**；
- **97% 以上的代码已完成基因重组与 100% 全新自主研发**；
- 系统已从单一的“命令行扫码传文件小工具”，演变为覆盖 **桌面端 GUI (Wails/Svelte)、现代移动端 Web 应用、即时聊天室、离线密码学授权 (DRM)、局域网 TLS 安全环回以及 Serverless 边缘云生态** 的全平台企业级局域网协同网络。

## 二、 依然保留的底座基因与开源传承（仅剩 ~3%）

在当前庞大的代码体量中，直接传承自原版 qrcp 的主要是**“工具级的轻量零件、命名习惯与最初的交互灵感”**：

1. **终端字符二维码渲染（`pkg/qr/qr.go`，约 30 行）**：
   - 使用 `github.com/skip2/go-qrcode` 库将局域网 URL 在控制台打印为黑白 ANSI 文本二维码的工具函数，因功能极其纯粹而保留。
2. **CLI 基础命令树骨架（`main.go` & `cmd/` 部分命令入口）**：
   - 基于 Cobra 构建的命令行基础参数结构：`send`、`receive`、`config`、`version` 等基础子命令的名字与基础标志定义继承了原有习惯。
3. **初始配置文件读取模型（`pkg/config/`）**：
   - 如 `port`、`interface`、`bind`、`keepAlive`、`path` 等最初字段的 YAML 映射骨架（但后续已大幅扩充桌面集成、DRM 证书、代理与更新策略）。
4. **核心交互灵感（产品的最初火种）**：
   - “通过二维码打通局域网跨设备直连，免数据线、免公网云盘中转”——这是最初的灵感源泉。
5. **合规与开源道德**：
   - 在项目根目录与头注释中严格保留原作者的版权声明与 MIT License。

## 三、 被彻底推翻重构的核心模块（看似同名，实则换心）

原版中最核心的两个模块，表面上目录路径与名字保留，但内部引擎已被彻底推翻重写：

### 1. 传输服务引擎（`pkg/server/server.go`）
- **原版 qrcp**（当时仅 **415 行**）：
  - 极简的单次传输：一个文件传完立刻强杀退出；
  - 完全不支持并发多设备，没有传输进度跟踪，没有速率统计；
  - 不支持分片、断点续传与 Range 协商，遇到 Safari 探测即刻报错终止。
- **现在的 EQT**（单文件 **3,882 行**，外加万行单元测试）：
  - **多设备并发状态机引擎**：设备活跃心跳、客户端独立记账、非阻塞内存状态快照微秒级轮询；
  - **双通道流式传输**：逐项物理文件直传（`0..N`）与整包 ZIP 归档传输（`-1`）数据通道严格隔离；
  - **HTTP RFC 7233 / 9110 Range 规范支持**：支持并行分片下载、Safari `bytes=0-1` 探测协商、Seek 时间轴播放与断点续传；
  - **高可用生命周期门禁**：`autoStop` 动态调度与 `KeepAlive` 守护长连接机制。

### 2. 浏览器前端交互页（`pkg/pages/`）
- **原版 qrcp**：
  - 只有几百行极其简陋的 HTML 字符串拼接；上传仅有一个原生表单 `<input type="file">`，下载页连进度条和文本折行都不具备。
- **现在的 EQT**：
  - 演进为**商业级现代响应式 Web App**：支持中英等多语言 i18n 动态切换、深浅色模式、超长文件名自适应折行、复制交互动画、息屏重连与后台探活、Telemetry 埋点探针。

## 四、 100% 自主研发的全新庞大子系统（占 95% 以上）

在脱离原版脚本化雏形后，EQT 全新自主研发了以下 6 大核心子系统，原版中完全不存在：

### 1. Wails 桌面端跨平台混合 GUI（`desktop/`，约 25,000+ 行）
- 彻底跳出纯命令行限制，打造了原生的桌面应用程序；
- 包含桌面常驻系统托盘、多任务卡片流水线、Windows/macOS 系统右键菜单集成、静默后台升级与崩溃自愈机制；
- 前端使用现代化 Svelte 响应式框架，实现数据状态与视图完全解耦。

### 2. Tus 开放断点续传协议管道（`pkg/server/server.go:3150+`）
- 引入开放 Tus 分块上传协议，切片校验、断点续传、抗移动端息屏弱网抖动；
- 配合传统的 Multipart 流式回退形成双层高可靠接收管线。

### 3. 即时通讯与附件流式分发系统（Chat v2，`pkg/chat/`，约 15,000+ 行）
- 自研局域网双向即时通讯系统：局域网房间建立、WebSocket 全双工消息同步、附件流式分发、免额超限平滑限速。

### 4. 离线密码学硬件指纹授权体系（DRM，约 10,000+ 行）
- 主板 UUID、CPU 序列号、物理磁盘序列号多维指纹采集与“空值防呆比对”；
- 基于 Ed25519 椭圆曲线数字签名实现 100% 离线授权校验；
- 配合 Cloudflare Serverless D1 边缘数据库完成在线鉴权与激活重置。

### 5. LAN-TLS 局域网通配符证书与环回安全上下文
- 自研 ACME DNS-01 挑战应答基础设施与证书加载管线，配合自动化工具签发局域网通配符证书；
- 无缝降级自签名机制，彻底解除移动端浏览器在局域网下对 Clipboard、WebRTC 等现代 API 的 Secure Context 限制。

### 6. Cloudflare 边缘生态体系（`cloudflare/`，约 15,000+ 行）
- 包含官方多语言宣传门户、Paddle 跨境支付网关集成、用户自助授权管理 Portal，以及全球 License 管理后台 Admin 看板。

## 五、 总结与工程启示

EQT 与 qrcp 的关系，可以用一个生动的比喻来总结：

> **“当初我们借了 qrcp 这辆‘自行车’的把手和车铃（扫码传输的点子与 CLI 命令行雏形）；但在这套底座上，我们亲手研发并装载了高功率发动机、航电雷达系统、流线型机身和智能驾驶座舱，将其彻底改装成了一架拥有自主航行能力的现代客机。”**

在法律合规与开源道德上，我们始终致敬并遵循开源前人的智慧；  
但在工程架构与产品形态上，EQT 早已完成了**脱胎换骨的物种跃迁**。
