# Chat 会话历史归档与持久化架构设计 (Chat Session History & Persistence Design)

**文档标识**：`docs/future/20260906-chat-session-history-and-persistence-design.md`  
**提案日期**：2026-09-06  
**状态**：未来功能规划 (Proposed for Future Roadmap)

## 一、背景与现状第一性原理分析

### 1.1 现有 Chat 模式的数据生命周期
- **纯内存与按需流式管道 (In-Memory & On-demand Streaming)**：
  - 目前 EQT Chat-v2 采用极其轻量和极致的端到端 Rendezvous 机制。
  - 远端（如手机端）发送文件时，仅广播消息元数据（文件名、体积、MIME 类型）。文件实体保留在发送方的浏览器句柄中，服务端不落盘、不建临时文件。
  - 只有当接收方（GUI 或对端）主动触发“下载/保存”时，才通过 WebSocket 唤醒发送方建立实时 HTTP 流管道，直写到目标保存路径。
  - **当前现状**：会话为“瞬态会话”（Ephemeral Session）。一旦 GUI 退出、服务重启或关闭页面，所有聊天记录、文字内容和未下载的流引用全部在内存中销毁，用户无法查阅过去的传输与沟通记录。

### 1.2 用户的核心诉求
1. **可回溯性**：用户需要在重启 EQT 或再次连接时，查阅与特定设备或历史会话中的文本交流、关键链接与传输清单。
2. **确定性与无负担**：
   - 已经保存/下载的文件：能够直接定位到本地磁盘路径（“在文件夹中显示”）。
   - 未下载的文件：明确标记为“已过期/发送方离线”，不给本地磁盘留下垃圾临时文件。
3. **隐私安全**：局域网传输应提供便捷的“一键抹除历史”和“会话留存周期控制”。

## 二、架构设计与核心机制

### 2.1 本地轻量化存储选型
为保障桌面端跨平台（Windows / macOS / Linux）轻便无依赖：
- **方案**：采用轻量级结构化存储（单文件 SQLite 或 JSONL 顺序日志，放置于应用数据配置目录）。
- **表结构/数据模型设计**：
  - `sessions`：
    - `id`: 会话唯一标识 (UUID)
    - `created_at`: 会话创建时间
    - `last_active_at`: 最后活跃时间
    - `devices`: 参与设备指纹与昵称快照 (JSON Array)
  - `messages`：
    - `id`: 消息唯一 ID (`msg-xxxx`)
    - `session_id`: 所属会话 ID
    - `sender_peer`: 发送方 Peer ID 与设备名
    - `type`: `text` | `file` | `system`
    - `content`: 文本内容或文件名
    - `size`: 字节数
    - `mime_type`: 媒体类型
    - `local_saved_path`: 若已下载/保存，记录本地绝对路径；未下载则为 null
    - `status`: `delivered` | `saved` | `expired`
    - `created_at`: 发送时间戳

### 2.2 附件生命周期与磁盘管理策略
1. **已下载的文件**：
   - 记录其物理存储路径（例如 `D:/Downloads/eqt/report.pdf`）。
   - 用户在历史面板中点击该文件卡片时，直接调用系统资源管理器定位。若文件被用户在磁盘上手动移动或删除，界面友好提示“本地原文件已不存在”。
2. **未下载的文件**：
   - **绝对不自动在会话目录产生垃圾缓存**（保持现有良好的零落盘机制）。
   - 若发送方与接收方当前**同时在线**，允许历史卡片补拉下载；
   - 若发送方已断开或会话已归档，卡片展示为“未下载（发送方已离线）”，彻底杜绝膨胀磁盘空间。

### 2.3 隐私防护与自动老化 (Retention Policy)
- **留存周期设置**：
  - 用户可在偏好设置中配置：`保留 7 天` / `保留 30 天` / `永久保留` / `退出时自动清除`。
- **一键清空**：
  - 提供“清空当前会话”与“抹除所有历史聊天记录”功能，保障隐私合规。

## 三、商业化分级规划 (Product Tiering)

结合 EQT 商业化授权规范：

| 功能特性 | 免费版 (Free) | 专业版 / 商业版 (Plus / Pro) |
| :--- | :--- | :--- |
| **会话历史留存** | 支持最近 3 个会话 / 最多保留 7 天 | **无限期留存** / 完整历史会话归档 |
| **检索与筛选** | 仅支持基础时间倒序浏览 | **全局全文检索**（搜索文字、文件名、发送设备） |
| **导出能力** | 仅屏幕复制 | **一键导出为 Markdown / HTML 结构化归档文件** |
| **跨设备历史同步** | 仅本地单机查看 | 支持局域网受信任设备间历史记录安全迁移/漫游 |

---

## 四、实施路线建议

1. **第一阶段 (Phase 1)**：在 Go 后端引入轻量持久化模块，定义数据模型与自动老化任务。
2. **第二阶段 (Phase 2)**：桌面 GUI 增加“历史会话 (History Sessions)”面板入口与消息查看抽屉。
3. **第三阶段 (Phase 3)**：支持全局检索、导出与商业化授权策略控制。
