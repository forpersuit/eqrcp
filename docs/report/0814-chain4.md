二、🔴 高严重度

H1. GUI 兑换/解绑/刷新按钮监听器叠加 → 重复激活

desktop/gui/frontend/src/main.js:3613（#confirm-redeem）、:3614/3618/3622（解绑按钮）、:3633（刷新）

render() 每次调用都会跑 bindEvents() → bindPanelEvents()，而 morphdom 会复用同 id 的 DOM 元素（不重建）。于是 addEventListener 在同一元素上反复叠加。代码作者已用 _staticDelegationBound 委托机制规避过此坑（L3011 注释），但兑换/解绑/刷新按钮没有走这套委托。

失败场景：点一次「兑换」→ confirmRedeem 内部 render() 两次 → 按钮累积 3 个监听器 → 第二次点击时 3 个监听器同步执行 → ActivateLicense(code) 连发 3 次。state.isActivating 入口无守卫（L5740），只靠 disabled 属性，而叠加监听完全绕过它，问题逐次放大（3→5→7…）。解绑、刷新按钮同理。

H2. resetLicense() 禁用了错误的按钮 → 重复解绑/重复 unbind

desktop/gui/frontend/src/main.js:5795-5797

重置确认态下 DOM 里渲染的是 #confirm-reset-license，而代码 querySelector('#reset-license')（该元素此时不在 DOM）拿到 null，真正被点的确认按钮从未被禁用，且 resetLicense() 不设 state.isActivating。

失败场景：双击「确认重置」→ 两次 ResetLicense() → 两次 SetPaidStatus(false) + 两次 /device/unbind 请求（后端 ResetLicense 无互斥锁）。

H3. auth.ts 源码硬编码 SMTP 密码回退（需立即核实）

cloudflare/eqt-drm-api/src/routes/auth.ts:254-257
const mailSenderPassword = env.MAIL_SENDER_PASSWORD || "q4W62}bWtR";
const mailSendServer = env.MAIL_SEND_SERVER || "smtpserver.301098.xyz";
当环境变量未配置时回退到源码中的明文凭据。若该值为真实可用凭据，等于已随仓库泄露；即使已失效也违反"凭据不入库"原则，且该默认值会掩盖"生产漏配 secret"的告警。建议：移除硬编码，未配置时直接抛错 fail-closed。

三、🟠 中严重度（跨层一致性 / 兑换正确性）

M-A. 指纹校验跨层不一致 → 单指纹设备激活必败 + 席位泄漏（客户端 C + 服务端 9）

- 客户端 license.go:287-289 前置只拒绝全空指纹，实际 VerifyFingerprint(:149) 要求 ≥2 项非空匹配；
- 服务端 drm.ts:353 只要求 ≥2 项非空、不校验真实性，且 verify 的设备匹配是"指纹 或 device_id"软匹配(:816)。

失败场景：WSL/部分 Linux 下 CPU serial、磁盘 serial 常取不到，只剩 UUID 一项 → 激活请求已上送服务端（占用一个 max_devices 席位）→ 客户端验指纹失败拒绝落盘 → 席位被占用且不释放，重试继续耗尽席位直至锁死。同时 device_id 软匹配可被伪造：攻击者用受害者 device_id + 2 个伪造哈希即可克隆授权。

M-B. 时钟篡改标志被 SetPaidStatus(false) 立即清除（客户端 A）

license.go:242-244 + chat_limiter.go:384
检测到时钟回拨先 SetClockTampered(true) 持久化，紧随的 SetPaidStatus(false) 经 SetPaidDetails 无条件把 ClockTampered 重置回 false 落盘。两条篡改检测路径行为不一致（chat_limiter.go:284-293 那路是对的），证明是 bug：篡改惩罚在重启后被静默解除。

M-C. 证书 read-modify-write 竞态丢失服务端同步结果（客户端 B）

license.go:172-174 读 → :262-264 写回，整体非原子。
后台 doOnlineLicenseSync 写入含最新 tier/expiry/verify_signature 的新证书时，前台 VerifyLocalLicense 若已先读到旧证书，随后把旧证书+新 LastSeenLocalTime 覆盖写回 → 续期/降级结果被旧数据吞掉。

M-D. 激活不校验 verify_signature，激活成功即被降级（客户端 D）

license.go:346-352 激活只验 VerifyLicenseSignature+VerifyFingerprint，不验同步签名；但随后启动必跑的 VerifyLocalLicense 会强制验同步签名。服务端若返回缺失/错误 verify_signature → 用户先见"激活成功"，数秒后降级 Unpaid（付费态闪烁，证书残留）。

M-E. 占位符 "未注册" 被当作 device_id 上送（客户端 E）

hardware.go:365 GetDeviceStableID() 在异步设备注册完成前回退返回字面量 "未注册"，激活请求 license.go:296 会把它当真实 device_id。之后 ResetLicense 解绑携带 cert.DeviceID="未注册" 与当前真实 device_id 不一致 → 服务端按 device_id 解绑失败，席位永久占用。

M-F. unbind_records INSERT 非幂等 → 年度解绑额度被重复扣减（服务端 4/5）

drm.ts:968-975 配额 INSERT 只 WHERE COUNT(*) < 4、无 NOT EXISTS 防重复；portal.ts:278-280 更是裸 INSERT。D1 重试（wrapD1WithRetry 对 run() 会重放）或并发双击解绑 → 一次解绑吃掉 2 个年度名额，突破 4 次/年反滥用上限。

M-G. Portal 解绑 TOCTOU + 非原子（服务端 5）

portal.ts:246-251 配额检查与 :272-280 的 DELETE/INSERT 分离，三个写操作非同一事务。并发两解绑都读到 unbindCount=3 < 4 → 都放行 → 当年 5 条记录；或 DELETE 成功、INSERT 抛错 → 席位已释放但未记账。

M-H. 激活失败前已写入 paid device_registry 幽灵记录（服务端 2）

drm.ts:504-512 注册设备写在条件 INSERT(:517) 之前且不依赖其成功。max_devices 满时第 3 台设备激活：先写 paid registry → INSERT changes=0 返回 403 → registry 永久多一条 paid 记录污染统计。

M-I. license-query 无鉴权泄露激活码（paddle 2.1）

paddle.ts:873-909 仅凭 transaction_id 即返回 license_code。transaction_id 出现在前端结账 URL/轮询中，任何能看到 URL/日志/Referrer 的人都可凭此取得激活码直接激活。

M-J. 铸码幂等安全网可被静默跳过（paddle 1.1）

utils/auth.ts:183-207 ensureLicensePaddleTxnIndex 发现存量重复 txn 时只打 WARN 并跳过建索引，从此 licenses.paddle_transaction_id 唯一约束永久缺失 → 并发同交易重投可双铸。建议改为发现重复即 CRITICAL 告警并 fail-closed。

M-K. tryLocalDevJwt 配置型管理员后门（paddle 8.1）

utils/auth.ts:364-377/429-434：当 CF_ACCESS_TEAM_DOMAIN='local.dev' 且 CF_ACCESS_AUD='local-dev' 时，任意 Cf-Access-Jwt-Assertion: local.<任意邮箱> 免签名即管理员。若本地 wrangler.toml 被误带入生产，管理 API 全开。

M-L. 退款 webhook 历史匹配整体吊销后续已付费期间（paddle 9）

paddle.ts:587-628/682-722 续期后 paddle_transaction_id 已指向最新 txn，退早期账期款项时历史/订阅回退匹配到同一 license → 整张 license（含后续已付账期）被吊销，过吊销风险。

M-N. Admin 解绑不降级 device_registry（服务端 6 / paddle 4.1，同一问题）

admin.ts:762-764/784 只 DELETE activations，不像设备端/Portal 解绑那样把 device_registry 降级为 free。解绑后设备仍显示 paid 并残留旧 license_code（且 device-registry.ts:112-121 有"付费保级"逻辑，后续 free 上报也无法回落）。

M-O. GUI localStorage 写失败误报激活/重置失败（GUI M2）

main.js:5735-5738 saveLicense 的 setItem、:5799 的 removeItem 无 try/catch。隐私模式/配额满时后端已成功但 UI 报"激活失败/重置失败"，授权状态与 UI 不一致。

四、🟡 低严重度（合并列出）

- GUI：hasPaidLicense 在 state.status 未加载时有 localStorage 抢权回退窗口（M1）；triggerManualRefresh 无入口节流且可能永久卡死（M4）；面板停留期间监听叠加（M3）；state.isActivating 等字段未在 state.js 声明（L1）；formatActivationError 把原始错误当翻译 key（L2）；首次同步用当前时间伪造 redeemedAt + 高频写 localStorage（L3）；非法日期显示 Invalid Date（L4）；重置失败未清 redeemMessage 致双 notice（L6）。
- Go：doOnlineLicenseSync TryLock 失败返回 nil 掩盖"未同步"（F）；写回 LastSeenLocalTime 不更新内存缓存（G）；EQT_TESTING/EQT_MOCK_STATUS 测试后门不受 build tag 约束（H）；对账 200+非OK 不降级（I）。
- Worker：changes===0 重试路径未用权威 activated_at 重算固化到期（drm 1）；并发注册同指纹产生重复 registry 行（drm 3）；解绑配额与清理非同一事务（drm 7）；吊销两步 UPDATE 非原子（drm 8）；Admin 解绑不写 unbind_records 致退款漏计（paddle 4.2）；退款计数只认 buyer_email_hash（5.1）；升级 pending 记录无迁移（6.1）；测试侧价格校验 hostname 判定跳过（7.1）；TEST_MAIL_RECEIVER 泄露 OTP（8.3）；target_license_code 续期归属 fail-open（10）；renew-checkout 错误码不一致（3.1）。
