# 通用软件工程宪法 (Universal Engineering Constitution)
> 版本: v1.0 | 适用范围: 任何语言、技术栈、架构与团队规模的软件工程

---

## 序章：适用范围与核心概念

本宪法适用于任何软件工程。它只规定**不变量（Invariants）与决策程序**，不硬编码具体的语言、工具或文件路径。具体项目的工具链与专有规约通过**项目绑定表（第五部分）**接入。

### 1. 初衷宣言 (The Prime Intent)
> **让委托变得安全且廉价：任何结论都带着可被第三方廉价核验的证据，任何行动都带着退路，任何裁判都独立于被裁判者。**
> 本宪法守护两样最高稀缺资源：**人类的注意力与信任**，以及**系统未来的修正自由（Optionality）**。
> 我们对抗的不是不可避免的错误，而是**被隐藏的错误、被放大的错误、以及被合理化的错误**。

### 2. 规则执行层级 (Enforcement Tiers)
宪法内的每条规则均显式标注执行层级，严禁口头承诺冒充硬门禁：
- **〔H〕Hard Invariant（硬不变量）**：有确定性的机器自动化门禁，违反即物理阻断。只有人类通过带工单和到期日的 Waiver 才能豁免。
- **〔E〕Evidenced（凭据约束）**：无法完全机检，但提交或交付时必须附带可复核的客观工件（命令输出、退出码、查询命中数）。
- **〔J〕Judgment（主观裁决）**：无自动化门禁，由 Reviewer 或人类依据 Rubric 进行审议，诚实说明无门禁。

### 3. 基本定理：作者不是验证者 (Author ≠ Verifier)
执行者（包括开发者与 AI Agent）的自我陈述不构成有效证据。**只有独立第三方的验证结论与未受污染的机器输出才构成证据。**

## 第一部分：元决策层 (Meta-Decisions & Arbitration)

### [M1] 优先级序 (Precedence Order) 〔H〕
执行仲裁与冲突调解的绝对优先级：
$$\mathbf{\text{机器门禁 (G)} > \text{项目反射表 (R)} > \text{宪法硬不变量 (I)} > \text{初衷推断}}$$
元原则与初衷仅用于“完全无规则匹配”的冷启动未知情境，绝对不得用于为违反反射规则或门禁开脱。

### [M2] 仲裁协议 (Arbitration Protocol) 〔E〕
当两条规则发生冲突时，以**“本仓库未来维护成本最低（Lowest Future Cost / Optimize for Deletion）”**为标尺裁决，但必须满足：
1. 显式列出至少两个备选方案，并对比其影响面（文件数、调用点数、可回滚性）；
2. 在提交说明中以 `Arbitration:` 显式留痕；
3. 仲裁使用频率受规则预算约束，禁止滥用为常规通行证。
*门禁形态：缺少仲裁留痕的冲突型提交将被机器拒绝。*

### [M3] 认知诚实声明 (Epistemic Honesty) 〔E〕
结论必须标注认知状态：未执行验证即写 `[未验证]`，严禁写“应该通过”；无法执行的检查必须显式声明无法执行的原因，严禁静默省略。

### [M4] 向规则本身要证据 (Rules Require Proof) 〔J〕
每一条规则必须具备可观测的违规谓词与门禁形态，或显式降级为 E/J。写不出违规谓词的规则视为安慰剂口头承诺，限期降级或删除。

### [M5] 规则生命周期与预算 (Rule Lifecycle & Budget) 〔E〕
每条项目级规则必须记录其“出生事件”（由哪次故障或事故催生）；反射表条数设硬上限；长期零触发的规则定期进入删除评审。宪法自身遵循“为删除而优化”。

## 第二部分：架构拓扑硬不变量 (Architectural Invariants)

### [I1] 单一领域所有权 (One Owning Module per Domain) 〔H〕
每个业务领域有且仅有一个模块拥有其核心逻辑与数据事实，外部仅通过公开契约调用。
- **违规谓词**：出现循环依赖，或在函数体内/非顶层作用域使用局部导入、动态加载来规避依赖检查。
- **门禁形态**：依赖图严格无环检测；禁止局部动态 import。
- **豁免**：无。出现循环说明职责归属根本错误，必须先做领域重聚（Consolidate）。

### [I2] 知识唯一 (DRY: One Home per Fact) 〔H/E〕
同一业务知识（算法、阈值、业务格式、状态判定）在系统内只有唯一的权威定义。
- **触发条件**：同一业务知识的第二次出现（Second-Use），而非表面文本巧合。
- **动作**：按 [W3] 堆叠两阶段变更法，先重构切旧调用，再接入新场景。禁止就地复制并微调。
- **门禁形态**：Token 级代码克隆检测；重构后排查查询的命中数必须归零。

### [I3] 表现层与适配层零业务决策 (No Business Logic in Presentation) 〔H〕
用户界面、模板、路由分发 Handler、CLI 外壳只负责排版、展示格式化与封闭枚举映射，严禁做业务决策。
- **判别三问（任一为“是”即属业务逻辑，必须下沉领域层）**：
  1. 第二客户端测试：若新增另一种客户端（CLI/API/移动端），这段逻辑是否需要重写一遍并保持一致？
  2. 规则测试：它是否对领域字段做了比较运算、阈值判断、权限判定或跨字段聚合推导？
  3. 后果测试：这段逻辑写错了，后果只是“显示难看”，还是“业务状态/金额/权限错误”？
- **契约下发**：业务层下发语义化纯值（如 `canRetry: bool`, `statusKind: enum`, `displayTotal: string`），表现层仅做声明式只读绑定。
- **门禁形态**：静态扫描表现层，禁止出现针对领域字段的比较、算术与多字段布尔链。

### [I4] 边界解析，内部可信 (Parse at Boundary, Trust Internally) 〔H/E〕
外部输入（HTTP 请求、外部文件、用户输入）只能在系统边缘解析一次，并转换为类型安全的强结构；系统内部传递强类型值，不再重复防御性校验，不再传递松散原始字符串。凭据与密钥严禁进入代码库。
- **门禁形态**：密钥与敏感信息静态扫描；核心领域禁止引用未解析的原始输入对象。

### [I5] 单向依赖方向 (Strict Layering Direction) 〔H〕
高层策略依赖抽象，不依赖低层细节；领域核心层严禁依赖表现层、框架句柄或具体基础设施。
- **门禁形态**：跨层依赖方向静态检查（如架构守护规则）。

### [I6] 显式状态机 (Explicit State Machines) 〔E/H〕
具有生命周期的实体必须使用显式状态枚举与转移表定义，使非法状态在代码结构中“不可表达”；每个合法状态转移具备测试，非法转移具备拒绝测试。

### [I7] 错误向上传播与大声失败 (Fail Loud) 〔H〕
错误必须被显式处理、包裹翻译或向上传播，严禁被无声吞掉伪装成正常流程。
- **违规谓词**：空 catch/except 块、忽略错误返回值、在错误分支擅自返回默认兜底值。
- **门禁形态**：静态扫描拦截空错误捕获与未检查的错误丢弃。

### [I8] 并发生命周期与状态归属 (Managed Concurrency) 〔H/E〕
每个异步任务、后台线程或协程必须具有明确的生命周期所有者、超时控制、取消传播路径与错误上升通道。跨任务共享状态必须具备显式并发同步策略，写操作需声明幂等性。
- **门禁形态**：竞态检测器（Race Detector）；后台孤儿任务扫描。

### [I9] 数据迁移可逆性 (Data Migration Optionality) 〔E〕
数据比代码更难回滚。数据结构变更必须遵循“扩展（Expand） $\rightarrow$ 迁移（Migrate） $\rightarrow$ 收缩（Contract）”的时序，保证向前向后双向兼容。不可逆操作必须显式打标并经人工双签。

## 第三部分：工作流与演进律 (Workflow & Change Disciplines)

### [W1] 意图先行 (Intent-First Discipline) 〔E〕
每次非平凡变更前，必须具备明确的意图陈述：包含明确假设、非目标（Non-goals）以及可证伪的成功验收条件。“测试验证意图”以此为对齐锚点。

### [W2] 外科手术式克制与 Touch Set (Surgical Changes) 〔H〕
- **Touch Set 铁律**：
  $$\text{Touch Set} = \text{实现该意图所必需的最小文件} + \text{被去重逻辑的所有调用点}$$
- **严禁顺手牵羊**：范围之外的瑕疵仅记录入待办清单，严禁在当前变更中顺手格式化、重命名或重构无关代码。
- **门禁形态**：变更文件超出预声明 Touch Set 时触发警报。

### [W3] 堆叠两阶段变更法 (Stacked Two-Phase Commits) 〔H〕
当变更涉及复用、抽离或移动已有逻辑时，**严禁在一个不可验证的混合 Diff 中同时做重构与新业务**，必须拆分为同一分支上的两个堆叠提交：
1. **Commit 1 (`Change-Type: refactor`)**：
   - 纯保真重构，提取公共逻辑并全量切换所有旧调用点。
   - **门禁铁律**：测试文件的 Diff 必须为空，且全量测试 100% 保持绿灯。这是行为保真最廉价、最硬核的物理证据。
   - 若原代码缺乏测试覆盖，先以独立提交补齐特征测试（Characterization Test），再行重构。
2. **Commit 2 (`Change-Type: feature`)**：
   - 基于已经稳定的抽象，挂接新增业务。
- **熔断机制**：若 Commit 1 影响文件数超过爆炸半径阈值 $N$，严禁在当前会话盲目扩大，必须停下向人类升级，并登记技术债务。

### [W4] 红绿测试优先 (Red-Green Verification) 〔E〕
修复任何缺陷前，必须先编写一个在当前问题代码上**可稳定复现失败（Red）**的测试用例；修复后变为通过（Green）。没有“先红后绿”的凭据，不得声称缺陷已被定位修复。

### [W5] 单一意图提交 (Single Intent per Commit) 〔H〕
每个 Git 提交必须对应一个单一、明确的意图，具备独立回滚能力。混杂了重构、排障与新特性的提交应被门禁拦截。

### [W6] 最简可用形态 (Simplicity & YAGNI) 〔J/E〕
不为“显得有技术深度”而引入未被当前需求证明的投机性抽象、过度分层、中间件或动态插件机制。新增任何抽象，必须证明它消除了现存的具体重复，或隔离了已明确发生过两次的变化。

## 第四部分：自动化门禁与交付律 (Gates, Not Promises & DoD)

### [G1] 测谎仪三件套 (The Anti-Cheating Meta-Gate) 〔H〕
作为优先级最高的门禁，拦截一切削弱判决系统的作弊行为：
1. **反吞错**：拦截空异常处理、忽略错误返回值、错误分支静默返回默认值。
2. **反压制**：拦截 Diff 中新增的跳过测试、压制告警标记（如 `skip`, `xfail`, `nolint`, `ts-ignore`, `as any`），无有效 Waiver 登记即刻阻断。
3. **反篡改裁判**：禁止在同一个提交中同时修改“被测代码”与“门禁配置/CI配置/测试断言”。弱化已有断言、删除既有测试视同篡改。门禁自身的修改必须由人类单独审批。

### [G2] 差异棘轮机制 (The Diff Ratchet) 〔H〕
门禁只强力阻断“本次 Diff 中新增的违规”，不阻断存量历史代码；存量违规记入技术债务基线，基线计数只降不升。

### [G3] 本地求快，CI 求真 (Fast Feedback, Authoritative CI) 〔H〕
本地 pre-commit / pre-push 钩子专注于秒级反馈；所有 Hard 级门禁必须在权威服务端 CI 重建纯净环境并重新执行，以 CI 结果为唯一仲裁事实。

### [G4] 独立验证环境 (Independent Verifier) 〔E〕
在多 Agent 或持续集成体系中，代码作者绝不充当验收裁判；验证者使用独立上下文，输入仅为 Diff、物理产物与验收标准，不包含作者的自我辩解。

### [G5] 带期限的豁免契约 (Expiring Waivers) 〔H〕
任何对硬规则的偏离，必须通过显式 Waiver 登记：包含理由、责任人（Owner）与过期时间。过期未修复者，门禁自动恢复阻断。

### [G6] 机器证据链交付 (DoD Standard) 〔E〕
任务交付汇报必须包含三大客观要素：
1. **修改清单**：对照 Touch Set 列出改动文件及其职责。
2. **物理验证证据**：列出实际执行的命令、真实退出码、测试通过数量。
3. **排查工件**：若声称“已排查全量调用点”，必须附带查询语句与命中数统计（重构后必须归零）。

### [G7] 门禁报错必须可行动 (Actionable Gate Errors) 〔H〕
任何门禁触发失败时，输出的报错信息必须明确指出：(1) 违反了哪条规则、(2) 为什么违反、(3) 推荐的标准修正路径。因为报错信息是出现在模型最近上下文中最具威力的纠偏文本。

## 第五部分：项目绑定接口 (Project Binding Specification)

通用宪法本身不包含具体项目的文件路径与技术细节。任何具体代码库通过在根目录编写**项目绑定表（Project Binding Profile）**接入生效。

### 项目绑定表必备骨架 (Template)
```markdown
# Project Binding Profile: <Project Name>

## 1. 技术栈与运行时声明 (Stack & Runtime)
- 编程语言、运行时版本、核心框架、构建与测试工具。

## 2. 确定性命令映射 (Command Mappings)
- `test`: 执行单元测试与集成测试的精确命令
- `lint`: 静态语法与代码风格检查命令
- `build`: 物理产物编译与打包命令
- `gate`: 门禁快速扫描脚本路径

## 3. 领域拓扑地图 (Domain Topology Map)
- 业务领域与拥有者模块对应表（Domain -> Owning Module）
- 表现层与适配层路径范围（Presentation / Adapters）
- 依赖分层流向定义（Allowed Import Graph）

## 4. 门禁工具落地映射 (Gate Implementation Map)
- 宪法 [G1] 测谎仪 -> 本技术栈的具体工具（如 golangci-lint / ESLint / custom script）
- 宪法 [I1] 拓扑无环 -> 本技术栈的依赖检查器（如 depguard / dependency-cruiser）
- 宪法 [I3] 表现层扫描 -> 模板 AST 检查脚本

## 5. 项目专属反射表 (Project Reflexes)
- 格式：触发条件 -> 强制动作 -> 违规后果/替代方案（每条记录出生事故事件）

## 6. 参数与阈值 (Parameters)
- 爆炸半径熔断阈值 N（文件数）
- 差异棘轮基线文件路径
- 规则预算上限

## 7. 活跃豁免账本 (Active Waivers)
- [Waiver-ID] 规则编号 | 豁免理由 | 责任人 | 到期时间
```
